# mortar-pestle-broadcast

The Broadcast engine for Mortar & Pestle: **libobs** (the OBS Studio core) embedded in a
standalone daemon process, supervised by the app and driven over an NDJSON named pipe
(`\\.\pipe\mortar-pestle-broadcast`). The app supplies its own UI in place of OBS's Qt
frontend; this crate is the engine side of that split.

## License boundary — read this before touching anything

**This crate is GPL-2.0-only** (see `LICENSE`). The rest of the Mortar & Pestle repository
is NOT. The boundary holds because the two sides are **separate programs communicating at
arm's length over a pipe protocol**, not one linked work:

- **GPL (this crate):** everything under `mortar-pestle-broadcast/` — the daemon, the
  bindgen-generated FFI bindings (generated from libobs's GPL headers, vendored at
  `vendor/obs-headers/`), any code ported or derived from the OBS Studio source tree, and
  the wire-protocol structs as defined *here*.
- **Not GPL (the app):** `src-tauri/`, `web/`, `modules/` — the app links nothing from this
  crate and shares no source with it. The app defines its own mirror of the wire protocol
  on its side (MIT); the protocol types are *mirrored by hand, never shared*. No code
  crosses the boundary in either direction.
- **Process boundary:** the app spawns/adopts this daemon as a child process and speaks
  newline-delimited JSON to it. That is mere aggregation / arm's-length IPC, the same model
  Streamlabs Desktop uses for its libobs host process.

Rules for contributors (enforced at PR review):

1. Code derived from OBS Studio source goes in this crate and nowhere else.
2. Never `use`/`include`/link anything from this crate in the app, or vice versa.
3. Protocol changes are made twice: once here, once in the app's mirror. Do not extract a
   shared crate.

## OBS payload

The daemon does not reinvent OBS — it loads the **official, signed** OBS runtime:

- `scripts/fetch-obs.ps1` downloads the pinned official OBS Windows x64 release zip +
  Sources tarball, stages the runtime at `obs/` (gitignored), vendors the libobs headers at
  `vendor/obs-headers/`, and generates `obs/lib/obs.lib` from `obs.dll`'s export table
  (dumpbin → .def → lib.exe). Pin + hashes recorded in `obs/PINNED.txt`.
- The signed binaries (notably the graphics-hook DLLs and virtualcam driver) ship
  **unmodified** — anti-cheat allowlists key on those signatures.
- `obs.dll` is **delay-loaded** (`/DELAYLOAD`): the exe starts without OBS on the loader
  path; the payload directory is added via `AddDllDirectory` before the first `obs_*` call.
- Payload root resolution order: `MORTAR_PESTLE_BROADCAST_OBS_DIR` env → beside the exe
  (prod bundle) → `<crate>/obs/` (dev).

## Bindings

`src/bindings.rs` is pre-generated by `scripts/regen-bindings.ps1` (bindgen CLI over
`vendor/obs-headers/`) and committed, so builds need no libclang. Regenerate only when the
OBS pin moves.

## Layout

- `src/main.rs` — CLI: `daemon` (the supervised engine), `probe <op> [json]` (dev/CI probe client)
- `src/obs/` — safe-ish wrappers over the bindings: startup, module load, scenes/sources/outputs, log routing
- `src/daemon/` — NDJSON pipe server, wire protocol, state → `StateSnapshot` projection
- `obs/` — staged OBS runtime payload (gitignored)
- `vendor/obs-headers/` — pinned libobs headers (GPL, part of this crate's corpus)
