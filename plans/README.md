## Cross-cutting reconciliations (read before executing test/doc plans)

1. **Rust test invocation is plan 002's job to pin — run 002 first.** `cargo test --lib` and *unfiltered* `cargo test --tests` trip a sandbox SIGTERM (the sidecar roundtrip tests spawn daemons). The safe path is per-target `--test <name>` / a filtered module run / the `scripts/verify.mjs` that 002 creates. Plans **020** and **023** still show unfiltered `--tests` in some verify lines and place their tests as in-file `#[cfg(test)]` *lib* mods; before running them, use 002's established safe invocation, and if lib-unit tests can't run under it, relocate them to integration targets (as **021** already did). **022/024** already follow 002's convention.
2. **Plan 016 was downgraded P1→P3 during writing.** The "broken DevServerPanel button on Windows" is already mitigated — `DevTab.jsx:39` gates the panel behind `VITE_TARGET_OS === 'linux'`, so it never renders on Windows. Residual work is comment cleanup only. The audit's `/usr/bin/npm` "rot" claim was **rejected**: that is correct `#[cfg(not(windows))]` code (Windows has its own resolver).
3. **Plan 027 doc placement.** `docs/DESIGN.md` **does** exist in-repo (a code-adjacent design-language doc, distinct from the vault's creative DESIGN.md — an early draft premise wrongly said it didn't; corrected in the plan). The CSS-ownership rule goes in `docs/DESIGN.md` beside plan 008's boundary note; code/state conventions go in a new `CONVENTIONS.md`.
